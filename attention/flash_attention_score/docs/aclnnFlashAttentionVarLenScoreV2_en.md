## Function

- Description: In the training scenario, the FlashAttention algorithm is used to implement self-attention computation. **The difference from [aclnnFlashAttentionScoreV2](./aclnnFlashAttentionScoreV2_en.md) is that this API supports variable-length S computation, meaning that multiple sequences of unequal lengths can be passed in at once. When using this API, query, key, and value are passed in TND format, where T stands for total number, representing the sum of lengths of all sequences. Meanwhile, actualSeqQLenOptional and actualSeqKvLenOptional are used to pass the cumulative length of each sequence in order to distinguish different sequences. The attention result is computed separately for each sequence.**
- Formula:

  The forward calculation formula of attention is as follows:

  - When psetype=1, the formula is the same as that of [aclnnFlashAttentionVarLenScore](./aclnnFlashAttentionVarLenScore_en.md).

  - When psetype is set to other values, the formula is as follows:

    $$
    attention\_out=Dropout(Softmax(Mask(scale*(query*key^T) + pse),atten\_mask),keep\_prob)*value
    $$

## Constraints

- Deterministic computation:
  - aclnnFlashAttentionVarLenScoreV2 defaults to a deterministic implementation.
- When this API is used with PyTorch, ensure that the versions of CANN-related packages and PyTorch-related packages match.
- The constraints on the input query, key, and value are as follows:
  - B: The batchsize must be equal.
  - D: The head dimensions must satisfy (qD == kD && kD >= vD).
  - The inputLayout must be consistent.
- Constraints on data shape:
    - T: The value range is 1 to 1M.
    - N: ranges from 1 to 256.
    - D: ranges from 1 to 768.
- The data layout format of query, key, and value only supports TND, where T is the tightly packed data of the B and S axes (SeqLenQ and SeqLenKV of each batch). B (Batch) indicates the input sample batch size, S (Seq-Length) indicates the input sample sequence length, H (Head-Size) indicates the hidden size, N (Head-Num) indicates the number of heads, and D (Head-Dim) indicates the smallest unit dimension of the hidden layer, satisfying D = H/N.
- realShiftOptional: If Sq is greater than 1024, Sq and Skv of each batch are of equal length, and the mask is a lower triangular mask with sparseMode set to 0, 2, or 3, alibi position encoding compression can be enabled. In this case, only the last 1024 rows of the original PSE need to be input to optimize memory usage, that is, alibi_compress = ori_pse[:, :, -1024:, :]. Details are as follows:
  - When the parameter differs for each batch, the shape is BNHSkv (H = 1024).
  - When the parameter is the same for each batch, the shape is 1NHSkv (H = 1024).
  - In TND scenarios, each batch segment is still generated as [N, Sq_i, Skv_i], but is flattened uniformly during storage and parameter passing. If the actual query length of the i-th batch segment is Sq_i and the actual key/value length is Skv_i, the number of PSE elements in the segment is N *Sq_i* Skv_i, and the total length of the entire PSE, pseTotalLen, is sum_i(N *Sq_i* Skv_i).
  - If pseType is 2 or 3, the data type must be FLOAT32, and the supported shapes are [B,N] or [N].
  - If this parameter is not used, pass nullptr to realShiftOptional and 1 to pseType.
- Meaning of each pseType value

    | pseType     | Meaning                       |      Note   |
    | ----------- | --------------------------------- | ----------|
    | 0           | Externally input pse: mul first, then add | - |
    | 1           | Externally input pse: add first, then mul | Consistent with the implementation of [FlashAttentionUnpaddingScoreGrad](../../flash_attention_score_grad/docs/aclnnFlashAttentionUnpaddingScoreGrad_en.md). |
    | 2           | Internally generated pse: mul first, then add | - |
    | 3           | Internally generated pse: mul first, then add, then sqrt | - |

- When pseType is 2 or 3, only equal-length Sq and Skv are supported.
- innerPrecise: Currently, 0 and 1 are reserved configuration values, and 2 enables the invalid-row computation, which prevents precision loss caused by full-row masks during computation but degrades performance. If the operator can determine that invalid rows exist (for example, sparseMode is 3 and Sq > Skv), the invalid-row computation is enabled automatically.
- Constraints on sparseMode are as follows:
  - When the shapes of all attenMaskOptional are smaller than 2048 and identical, it is recommended to use the default mode to reduce memory usage.
  - When configured as 1, 2, or 3, the user-configured preTokens and nextTokens do not take effect.
  - When configured as 0 or 4, ensure that attenMaskOptional is consistent with the ranges of preTokens and nextTokens.
  - If not explicitly specified, it is recommended to pass 0.
  - For details about different sparse modes, see [sparseMode Introduction](../../../docs/en/context/sparse_mode_introduction.md).
  - When configured as 3, invalid row computation is not supported, and Sq <= Skv must be satisfied for each batch.
  - When configured as 7, the optional input realShiftOptional is not supported.
  - When configured as 8, the optional input realShiftOptional is supported when q and kv of each sequence have equal lengths, and pse is generated globally. Outward slicing in the q direction is supported, which requires that q and kv of each sequence have equal lengths before outward slicing, and after outward slicing, actualSeqQLenOptional[0] - actualSeqKvLenOptional[0] + qStartIdxOptional - kvStartIdxOptional == 0 (this feature is experimental).
- In some scenarios, if the computation workload is too large, the operator execution may time out (aicore error with errorStr: timeout or trap error). In this case, axis splitting is recommended. Note: The computation workload here is affected by parameters such as B, S, N, and D. Larger values result in a heavier workload.
- In the band scenario, preTokens and nextTokens must have an intersection.
- In the prefixOptional sparse computation scenario (sparseMode=6), when Sq > Skv, the N value of prefix ranges from [0, Skv]; when Sq <= Skv, the N value of prefix ranges from [Skv-Sq, Skv].
- The actualSeqQLenOptional input supports an S length of 0 on a certain batch, but the optional input realShiftOptional is not supported in this case. The length of actualSeqQLenOptional has a value range of 1 to 2K. When the prefixOptional input is present, its maximum length is 1K.
- The attenMaskOptional input does not support padding, meaning that attenMaskOptional cannot contain any row where all values are 1.
- An S length of 0 on a certain batch in actualSeqQLenOptional is supported. If S is 0, the pse input is not supported.
  Assume that the actual S length is [2, 2, 0, 2, 2], then the passed actualSeqQLenOptional is [2, 4, 4, 6, 8].
